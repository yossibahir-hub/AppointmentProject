שלב 1: מערכת ניהול תורים

📝 מערכת ניהול תורים לקליניקה - יופי טופי
מערכת מלאה לקביעה, ניהול, עדכון וביטול תורים (CRUD) לקליניקת קוסמטיקה. המערכת בנויה בארכיטקטורת שכבות (מודולרית), משתמשת במסד נתונים שומר מצב (SQLite), וכוללת ממשק משתמש גרפי (GUI) מתקדם הבנוי ב-Tkinter.

🏗️ ארכיטקטורת הפרויקט (קבצים)
הפרויקט מחולק ל-4 קבצים מרכזיים כדי לשמור על קוד נקי, מודולרי וקל לתחזוקה:

database_conn.py (שכבת הנתונים):

אחראי על יצירת החיבור (Connection) למסד הנתונים CosmetiClinic.db.
מכיל את הפונקציה setup_database() שמייצרת את הטבלאות הטריגרים וה-מבטים הנדרשים באתחול הראשון של המערכת.
appointment_manager.py (הלוגיקה העסקית):

אחראי על כל פעולות ה-CRUD (יצירה, קריאה, עדכון, מחיקה) מול מסד הנתונים.
מבצע שליפות מידע (SELECT), כגון: get_available_times_for_date, get_all_appointments, get_appointment_by_id.
מנהל את העדכונים (INSERT, UPDATE, DELETE).
date_picker.py (רכיב התאריכון):

משתמש בספריית tkcalendar כדי להציג חלון קופץ (Pop-up מודאלי) לבחירת תאריך.
מונע בחירת תאריכי עבר.
מונע בחירת ימי שבת (אינדקס 5) ומועדונים מוגדרים מראש (חגים/חופשות).
main_clinic.py (ממשק המשתמש - GUI):

הקובץ הראשי שמריץ את התוכנה.
בנוי ממחלקת ClinicApp המנהלת את חלונות ה-Tkinter במצב מסך מלא / מוגדל.
כולל טפסי קלט, כפתורים, תפריטים נפתחים והודעות קופצות (messagebox).
מנהל את ולידציות המשתמש ברמת הממשק (שדות ריקים, זמני עבר וכו').

**DLL_params.py ( קובץ ניהול ועריכה של פרמטרים עיקריים במערכת כמו פרטי בסיס הנתוני סוגי תור הזמינים בקליניקה

🗄️ מבנה מסד הנתונים (SQLite)
במערכת קיימות שתי טבלאות מרכזיות המנהלות את המידע:

1. טבלת תורים (scheduled_appointments)
שומרת את המידע המלא על כל תור שנקבע בפועל על ידי הלקוחות.

id (INTEGER, PRIMARY KEY, AUTOINCREMENT) - מזהה ייחודי לכל זימון תור.
client_name (TEXT) - שם הלקוח/ה.
service (TEXT) - סוג הטיפול (מתוך רשימה מוגדרת מראש, כגון: טיפול פנים, הסרת שיער וכו').
date (TEXT) - תאריך התור בפורמט YYYY-MM-DD.
time (TEXT) - שעת התור בפורמט HH:MM.
client_phone (TEXT) - שם הלקוח/ה.
is_deleted (INTEGER) - דגל בוליאני ( מבוטל=1, 0 = תפוס).
updatedate (TEXT) -datetime תאריך ושעת עדכון הרשומה בפורמט
2. טבלת מאגר זמינות (appointments_repository)
שומרת את כל משבצות הזמן האפשריות של הקליניקה ומנהלת את הסטטוס שלהן למניעת כפילויות.

id (INTEGER, PRIMARY KEY, AUTOINCREMENT) - מזהה ייחודי לכל שעת תור.
date (TEXT) - תאריך המשבצת.
time (TEXT) - שעת המשבצת.
is_available (INTEGER) - דגל בוליאני (1 = פנוי, 0 = תפוס).
updatedate (TEXT) -datetime תאריך ושעת עדכון הרשומה בפורמט
3."main"."v_customers_data" - customers view
client_phone, client_name, today, total_visits, last_visit, future_visit

⚙️ תהליכים ופונקציונליות מרכזית
1. קביעת תור חדש (add_appt)
המשתמש מזין שם ובוחר טיפול מתפריט נפתח (OptionMenu).
המשתמש לוחץ על כפתור התאריך, הפותח חלון לוח שנה (ללא תאריכי עבר או שבתות).
לאחר בחירת תאריך, המערכת מתשאלת את מסד הנתונים (appointments_repository) שולפת רק את השעות בהן is_available = 1 וטוענת אותן לתפריט שעות נפתח.
בעת השמירה, התור נכנס לטבלת scheduled_appointments, והמשבצת בטבלת הזמינות מעודכנת ל-0 (תפוס).
2. עדכון תור קיים (update_appt)
המשתמש מתבקש להזין מזהה (ID) של תור קיים.
המערכת שולפת את פרטי התור מהמסד וממלאת את הטופס מראש.
שדה השם ננעל לעריכה (state="disabled").
התפריט הנפתח של השעות כולל את השעות הפנויות באותו היום + השעה הנוכחית של התור הקיים.
3. ביטול תור (delete_appt)
המשתמש מתבקש להזין מזהה (ID) למחיקה.
פונקציית המחיקה בודקת את ה-rowcount. אם לא קיים ID, מוקפצת שגיאה בחזית.
(במערכת מלאה, השורה מוסרת מ-appointments_repository והמשבצת בטבלת הזמינות חוזרת להיות 1).
4. צפייה בתורים (view_appts)
שליפת כלל התורים ממסד הנתונים ממוינים לפי תאריך ושעה.
תצוגה נקייה למשתמש באמצעות חלונית מידע (messagebox).
5. צפייה בפרטי לקוחות (view_customers)
שליפת כלל התורים ממסד הנתונים ממוינים לפי תאריך ושעה.
תצוגה נקייה למשתמש באמצעות חלונית מידע (messagebox).
6. ולידציות (בדיקות תקינות)
חובה למלא את כל השדות.
לא ניתן לבחור מועד שהזמן שלו (תאריך ושעה) עבר ביחס לזמן הנוכחי (datetime.now()).
ה-Pop-ups של הולידציות מוגדרים עם parent כדי לא להסתתר מאחורי המסך המלא.

שלב 2:
🤖 מערכת צ'אט-בוט חכם לניהול תורים לקליניקה (Full-Stack Web App)
הרחבה וובית מלאה למערכת ניהול התורים של קליניקת "יופי טופי". המערכת משלבת שרת API מבוסס FastAPI, ממשק צ'אט וובי מבוסס Streamlit התומך ב-RTL (עברית), ומנוע AI מבוסס Gemini 2.5 Flash עם תמיכה ב-Tool Calling (Function Calling) לשליפת נתונים מתוך מסד הנתונים SQLite.

🏗️ מבנה הרכיבים והקבצים החדשים
1. api_server.py (שרת ה-Backend & AI Engine)
שרת מרכזי שנבנה ב-FastAPI וממלא שני תפקידים עיקריים:

חשיפת אנדפוינטים לנתונים (REST API):
GET /api/customers/search/{name}: בדיקה האם לקוח קיים במערכת לפי שם בטבלה/תצוגה v_customers_data.
GET /api/appointments/{client_phone}: שליפת כל התורים המוזמנים של הלקוח מ-scheduled_appointments בפורמט JSON.
ניהול שיחת ה-AI מול Gemini:
מקבל את היסטוריית השיחה מ-app.py באנדפוינט POST /api/chat.
מגדיר את ה-Tools עבור Gemini (check_customer_by_name ו-get_appointments_by_phone).
מנהל את השרשרת של ה-Function Calling (קריאה ראשונה ל-Gemini ➔ הפעלת הפונקציה המקומית ➔ החזרת התוצאה ל-Gemini ➔ יצירת תשובה סופית בשפה טבעית).
2. app.py (ממשק ה-Frontend בצ'אט - Streamlit)
ממשק משתמש וובי נקי ומעוצב ללקוחות הקצה:

תמיכה מלאה ב-RTL: כולל הזרקת CSS מותאם אישית המיישר את בועות הצ'אט, חלון הקלט, הפונטים והאייקונים לימין.
ניהול זיכרון שיחה (st.session_state): שומר על היסטוריית השיחה הרציפה.
מנגנון הגנת עומס (Timeout): שולח בקשות B2B מול ה-API עם טיימאאוט ומציג הודעות שגיאה אדיבות בעברית במידה ושיחה נתקעת או שרת ה-API אינו זמין.
3. logger.py (מנגנון התיעוד)
רכיב אחראי על מעקב ותיעוד שאילתות מסד הנתונים:

תופס כל קריאה של cursor.execute ומקבל את פקודת ה-SQL ואת הפרמטרים שנשלחו.
רושם אוטומטית שורת לוג עם חותמת זמן (Timestamp) לקובץ log.txt.
4. chatbot_service.py (פונקציות ה-Tools)
מכיל את פונקציות העזר המגדירות את הקריאות הפנימיות ל-API:

check_customer_by_name(name): מתקשרת מול האנדפוינט החיפושי ומחזירה תגובת JSON.
get_appointments_by_phone(client_phone): מתקשרת מול אנדפוינט התורים ומחזירה JSON של התורים המתוכננים.
5. קובץ ה-.env (ניהול אבטחה ומפתחות)
קובץ סודי המשמש לאחסון משתני סביבה.

תכולה:
GEMINI_API_KEY=your_actual_gemini_api_key_here

חשיבות: שומר על מפתח ה-API מחוץ לקוד המקור כך שלא ייחשף במאגרי קוד כמו GitHub.
🛠️ דרישות מוקדמות והתקנת ספריות
יש לוודא שהותקנו כל הספריות הנדרשות לפרויקט:

pip install fastapi uvicorn streamlit google-genai requests python-dotenv

🚀 הוראות הפעלה מפורטות (שלב אחר שלב)
כדי להריץ את האפליקציה בצורה תקינה יש להפעיל שני טרמינלים נפרדים במקביל:

שלב 1: הגדרת מפתח ה-API
ודא שקיים קובץ .env בתיקיית השורש של הפרויקט המכיל את מפתח ה-Gemini שלך:

GEMINI_API_KEY=sk-xxxx-YOUR-API-KEY-HERE

שלב 2: הרצת שרת ה-Backend (FastAPI)
פתח טרמינל ראשון, נווט לתיקיית הפרויקט והרץ:

uvicorn api_server:app --reload

השרת יעלה ויקשיב לכתובת: http://localhost:8000
ניתן לצפות בתיעוד ה-API האוטומטי בכתובת: http://localhost:8000/docs
שלב 3: הרצת ממשק ה-Frontend (Streamlit)
פתח טרמינל שני, נווט לתיקיית הפרויקט והרץ:

streamlit run app.py

חלון הדפדפן ייפתח אוטומטית בכתובת: http://localhost:8501
כעת תוכל להתכתב עם הצ'אט-בוט בשפה טבעית!
