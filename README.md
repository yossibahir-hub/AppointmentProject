# 📝 מערכת ניהול תורים לקליניקה - יופי טופי

מערכת מלאה לקביעה, ניהול, עדכון וביטול תורים (CRUD) לקליניקת קוסמטיקה.
המערכת בנויה בארכיטקטורת שכבות (מודולרית), משתמשת במסד נתונים שומר מצב (SQLite), וכוללת ממשק משתמש גרפי (GUI) מתקדם הבנוי ב-Tkinter.

---

## 🏗️ ארכיטקטורת הפרויקט (קבצים)

הפרויקט מחולק ל-4 קבצים מרכזיים כדי לשמור על קוד נקי, מודולרי וקל לתחזוקה:

1. **`database_conn.py` (שכבת הנתונים):**
   - אחראי על יצירת החיבור (Connection) למסד הנתונים `CosmetiClinic.db`.
   - מכיל את הפונקציה `setup_database()` שמייצרת את הטבלאות הטריגרים וה-מבטים הנדרשים באתחול הראשון של המערכת.


2. **`appointment_manager.py` (הלוגיקה העסקית):**
   - אחראי על כל פעולות ה-CRUD (יצירה, קריאה, עדכון, מחיקה) מול מסד הנתונים.
   - מבצע שליפות מידע (SELECT), כגון: `get_available_times_for_date`, `get_all_appointments`, `get_appointment_by_id`.
   - מנהל את העדכונים (INSERT, UPDATE, DELETE).

3. **`date_picker.py` (רכיב התאריכון):**
   - משתמש בספריית `tkcalendar` כדי להציג חלון קופץ (Pop-up מודאלי) לבחירת תאריך.
   - מונע בחירת תאריכי עבר.
   - מונע בחירת ימי שבת (אינדקס 5) ומועדונים מוגדרים מראש (חגים/חופשות).

4. **`main_clinic.py` (ממשק המשתמש - GUI):**
   - הקובץ הראשי שמריץ את התוכנה.
   - בנוי ממחלקת `ClinicApp` המנהלת את חלונות ה-Tkinter במצב מסך מלא / מוגדל.
   - כולל טפסי קלט, כפתורים, תפריטים נפתחים והודעות קופצות (messagebox).
   - מנהל את ולידציות המשתמש ברמת הממשק (שדות ריקים, זמני עבר וכו').

## 🗄️ מבנה מסד הנתונים (SQLite)

במערכת קיימות שתי טבלאות מרכזיות המנהלות את המידע:

### 1. טבלת תורים (`scheduled_appointments`)
שומרת את המידע המלא על כל תור שנקבע בפועל על ידי הלקוחות.
* `id` (INTEGER, PRIMARY KEY, AUTOINCREMENT) - מזהה ייחודי לכל זימון תור.
* `client_name` (TEXT) - שם הלקוח/ה.
* `service` (TEXT) - סוג הטיפול (מתוך רשימה מוגדרת מראש, כגון: טיפול פנים, הסרת שיער וכו').
* `date` (TEXT) - תאריך התור בפורמט YYYY-MM-DD.
* `time` (TEXT) - שעת התור בפורמט HH:MM.
* `client_phone` (TEXT) - שם הלקוח/ה.
* `is_deleted` (INTEGER) - דגל בוליאני (  מבוטל=1, 0 = תפוס).
* `updatedate` (TEXT) -datetime תאריך ושעת עדכון הרשומה בפורמט  

### 2. טבלת מאגר זמינות (`appointments_repository`)
שומרת את כל משבצות הזמן האפשריות של הקליניקה ומנהלת את הסטטוס שלהן למניעת כפילויות.
* `id` (INTEGER, PRIMARY KEY, AUTOINCREMENT) -  מזהה ייחודי לכל שעת תור.
* `date` (TEXT) - תאריך המשבצת.
* `time` (TEXT) - שעת המשבצת.
* `is_available` (INTEGER) - דגל בוליאני (1 = פנוי, 0 = תפוס).
* `updatedate` (TEXT) -datetime תאריך ושעת עדכון הרשומה בפורמט

## ⚙️ תהליכים ופונקציונליות מרכזית

### 1. קביעת תור חדש (`add_appt`)
- המשתמש מזין שם ובוחר טיפול מתפריט נפתח (OptionMenu).
- המשתמש לוחץ על כפתור התאריך, הפותח חלון לוח שנה (ללא תאריכי עבר או שבתות).
- לאחר בחירת תאריך, המערכת מתשאלת את מסד הנתונים (`appointments_repository`) שולפת רק את השעות בהן `is_available = 1` וטוענת אותן לתפריט שעות נפתח.
- בעת השמירה, התור נכנס לטבלת `scheduled_appointments`, והמשבצת בטבלת הזמינות מעודכנת ל-`0` (תפוס).

### 2. עדכון תור קיים (`update_appt`)
- המשתמש מתבקש להזין מזהה (ID) של תור קיים.
- המערכת שולפת את פרטי התור מהמסד וממלאת את הטופס מראש.
- **שדה השם ננעל** לעריכה (`state="disabled"`).
- התפריט הנפתח של השעות כולל את השעות הפנויות באותו היום + השעה הנוכחית של התור הקיים.

### 3. ביטול תור (`delete_appt`)
- המשתמש מתבקש להזין מזהה (ID) למחיקה.
- פונקציית המחיקה בודקת את ה-`rowcount`. אם לא קיים ID, מוקפצת שגיאה בחזית.
- (במערכת מלאה, השורה מוסרת מ-`appointments_repository` והמשבצת בטבלת הזמינות חוזרת להיות `1`).

### 4. צפייה בתורים (`view_appts`)
- שליפת כלל התורים ממסד הנתונים ממוינים לפי תאריך ושעה.
- תצוגה נקייה למשתמש באמצעות חלונית מידע (messagebox).

### 5. צפייה בפרטי לקוחות (`view_customers`)
- שליפת כלל התורים ממסד הנתונים ממוינים לפי תאריך ושעה.
- תצוגה נקייה למשתמש באמצעות חלונית מידע (messagebox).

### 6. ולידציות (בדיקות תקינות)
- חובה למלא את כל השדות.
- לא ניתן לבחור מועד שהזמן שלו (תאריך ושעה) עבר ביחס לזמן הנוכחי (`datetime.now()`).
- ה-Pop-ups של הולידציות מוגדרים עם `parent` כדי לא להסתתר מאחורי המסך המלא.
